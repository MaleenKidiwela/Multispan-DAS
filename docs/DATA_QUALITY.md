## Data quality: known issues and how to correct them

A checklist for anyone using the OOI multispan DAS records (Nov 5, 2025 – Jan 28, 2026). Each row gives the issue, how to spot it, what it does if ignored, and the correction used here, with the code that implements it. This file is the project copy; the same section is in the report artifact ("Data quality and corrections").

**The five that matter most.** (1) Dropped data chunks make sample times wrong by up to 16 min: always time samples from the per-chunk metadata. (2) Every acquisition setup has its own time offset (latency) relative to UTC: calibrate it per setup before combining DAS with any other instrument. (3) Masked recordings still contain non-physical channels, including at both fault crossings: test channel quality before use. (4) Acquisition-setup changes can cause steps: never compare or inject across a setup change. (5) The north cable's polarity is opposite to the south cable's: flip it whenever the two are combined.

### External references

-   **Offshore catalogue locations** (PNSN) use onshore stations only (azimuthal gap about 250°); they are not ground truth for validating DAS locations. Onshore events (e.g. the Nov 23 M3.2 Amity) and global locations of large events are.
-   **Seismometer horizontal orientation** (HYSB1, HYS14) is unresolved; it does not bias dv/v because each component is measured against its own reference.

### Recommended processing recipe

1.  Build the inventory from `proc_start`; label each file's setup.
2.  Time samples per chunk; regrid with flagged gaps; reject windows &gt; 10 % empty.
3.  Test channel quality per block and setup; use 1-km bins of good channels; exclude C3 and noisy near-shore stretches.
4.  Normalise with running absolute mean (20 s); whiten in band.
5.  For absolute time, calibrate the latency of each setup against HYSB1 (or a simultaneous stream with a known latency).
6.  Use coda-only windows that start after the measured end of the ballistic packet; back-stack 24/48 h with a 1-h step; check with even/odd floors and an injection test inside one setup.
7.  Flip the north-cable polarity when combining the cables; never compare across setup changes without a step test.

### Recommendations for the data providers

-   Document dropped chunks and the trailer fields; update the example notebook to time samples from `gpu_idx` or the per-chunk `proc_start`.
-   Publish the latency of each acquisition setup and the polarity convention of each interrogator.
-   Export the chunk metadata for the hand-downsampled Nov 6–26 files, if the raw files still exist.
-   Flag non-physical channels (including the fault crossings) in the metadata, and keep file lengths of at least 30 min.
